# Building and flashing

## 1. Toolchain

Nothing is installed system-wide. PlatformIO lives in a venv inside this repo
and its package cache is redirected into `.pio-core/`:

```bash
cd desk-buddy
python3 -m venv .venv-pio
./.venv-pio/bin/python -m pip install platformio esptool
```

Then either use `tools/build_release.sh`, which sets `PLATFORMIO_CORE_DIR` for
you, or export it yourself:

```bash
export PLATFORMIO_CORE_DIR="$PWD/.pio-core"
```

## 2. Compile

```bash
cd desk-buddy/firmware
PLATFORMIO_CORE_DIR="$PWD/../.pio-core" ../.venv-pio/bin/pio run
```

The first run downloads the Espressif32 platform, the RISC-V toolchain and the
libraries — a few hundred MB, so give it time.

## 3. Flash over USB

Two images have to be written: the application and the LittleFS web panel.

```bash
../.venv-pio/bin/pio run -t upload      # firmware
../.venv-pio/bin/pio run -t uploadfs    # web panel (index.html, app.js, style.css)
```

Watch the boot log with `../.venv-pio/bin/pio device monitor`. On the C3 the
USB-Serial/JTAG port usually shows up as `/dev/cu.usbmodem*`.

If uploads fail, hold **BOOT**, tap **RESET**, release **BOOT** to force the
bootloader, then retry.

## 4. Build a one-click installer

This produces three files in `web-flasher/`:

| File | Flashed at | Contents |
|---|---|---|
| `desk-buddy-firmware.bin` | `0x0` | bootloader + partition table + application |
| `littlefs.bin` | `0x3b0000` | the web panel |
| `manifest.json` | — | generated by the script, so the offsets cannot drift |

The two images are kept separate on purpose. Merging the filesystem into the
firmware would force esptool to pad the gap up to the spiffs offset, turning a
1.3 MB download into a 4 MB one.

```bash
./tools/build_release.sh
```

## 5. Serve the installer

Web Serial requires a secure context, so `file://` will not work.

**Locally:**

```bash
cd web-flasher && python3 -m http.server 8000
# open http://localhost:8000
```

**Vercel** is the easiest public option, because it is HTTPS by default (which
Web Serial requires) and has no build step to get wrong. A `vercel.json` is
already in `web-flasher/` with the headers this needs.

Deploy with the CLI — the folder becomes the site root:

```bash
cd web-flasher
npx vercel --prod
```

Or connect the Git repo and set, in the project settings:

| Setting | Value |
|---|---|
| Root Directory | `desk-buddy/web-flasher` |
| Framework Preset | Other |
| Build Command | *(empty)* |
| Output Directory | *(empty)* |

**Do not point the Root Directory at the repo root** — Vercel will look for a
site there and the flasher will 404.

Two Vercel specifics worth knowing:

- **Deployment protection.** If Vercel Authentication is on for the deployment,
  the page needs a login before it loads. Fine for you, but it breaks any link
  you share. Check *Settings → Deployment Protection*.
- **On the Hobby plan** the terms are for non-commercial use. A personal desk
  buddy is fine; a product page selling kits is not.

**GitHub Pages or any static HTTPS host** also works — it is exactly how sites
like leroyd.com distribute firmware: a static page, a `manifest.json`, and the
image files.

### The control panel can never be hosted this way

Only the *installer* can live on Vercel. The control panel at
`firmware/data/` must be served by the ESP32 itself, because an `https://` page
cannot open a plain `ws://` socket to your device — the browser blocks it as
mixed content. Putting the panel on Vercel would load the UI but never connect.

## 6. The two pages, and why

| Page | Lives on | Job |
|---|---|---|
| **Installer** (`web-flasher/`) | GitHub Pages / localhost | Flashes firmware over USB. |
| **Control panel** (`firmware/data/`) | The ESP32 itself | Faces, message, sound, WiFi. |

The installer can never be the control panel: an `https://` page is blocked by
the browser from opening a plain `ws://` socket to your device (mixed content).
Serving the panel from the device also means it works with no internet at all.

## Troubleshooting

**Nothing on the OLED.** Check the I2C address first — run an `I2CScanner`
sketch. Some 1.3" panels are SH1106, not SSD1306, and need a different driver.
Confirm SDA→GPIO4 and SCL→GPIO5.

**No audio.** Missing 1 kΩ resistor, reversed TX/RX, wrong file naming, or an
under-decoupled 5 V rail. Open the control panel: if it says *no DFPlayer*,
the module never answered on UART.

**Web panel unreachable.** `http://buddy.local` relies on mDNS, which some
routers and Windows setups ignore. Use the IP the device prints on the serial
console instead.

**Accented text looks wrong.** Expected — the Adafruit GFX default font is
ASCII-only. Accents are folded (`é` → `e`) and emoji are dropped. Real glyph
coverage means embedding a custom GFX font.
